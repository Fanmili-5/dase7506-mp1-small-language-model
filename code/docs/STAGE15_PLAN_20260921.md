| G | Same B architecture, 3x duration cosine schedule | 21600 | 176,947,200 |

Maximum new training targets: 353,894,400. G is a duration/extra-compute experiment,
NOT an equal-target architectural win. A fixed longer cosine schedule is declared
before the run; the 7200-step intermediate G checkpoint has a different learning
rate history from B, so is not a clean matched-duration endpoint control.

Instantiated parameter counts: D 5,247,744; E 5,313,794; F 6,855,169;
G 5,280,769. All four full-context random-initialization FP32 output checks
are finite and normalized. This is contract evidence, not quality evidence.

D builds B, consumes the same initialization RNG, then removes copy parameters.
Backbone weights and RNG immediately after initialization match B exactly (tested).
This aligns initial dropout RNG and sampling; it does not force subsequent weights
or optimizer trajectories to match. E and F need not share dropout streams with B.

E uses three distributions: vocabulary softmax, existing content copy, and a new
successor route. At prediction position t, successor keys are h_j and values are
x_(j+1), with **j < t**. Thus every accessible value is in x_0,...,x_t. This is
implemented with a strict lower-triangular mask, and position 0 disables this route.
Each route has a learned query/key projection (64 dimensions). Three-way gate
logits are [0, content_gate(h_t), successor_gate(h_t)], initialized [0,-2,-2].
No network, mutable persistent cache, validation answers or cross-window state.

Two-sentence rationale: current copying helps repetition but can select past words
without adequately matching their preceding contexts. The added route retrieves
an already-observed continuation using predictive-context similarity; a learned
gate may exploit it when useful and retain vocabulary prediction otherwise.
Strongest objections: overlapping routes may add no information, steal probability
from novel targets, or cost too much CPU. Reject if measured quality/resources fail.

## Gates and cost accounting

- Run unit contracts (including strict successor alignment, first-token behavior,
  window/batch independence, finite gradients, serialization, CUDA BF16).
- All four random-initialization candidates get three alternating CPU FP32 full
  validation resource repetitions before training. Reject >5x, >4GiB or >64MiB.
  Mark near-5x models as fragile; preflight never establishes model quality.
- First two actual updates then exact optimizer/RNG resume, not extra training.
- Evaluate every 300 updates, but primary selection uses only fixed final-five
  weight averaging: short runs 6000/6300/6600/6900/7200; long run
  20400/20700/21000/21300/21600. Also report unaveraged endpoint separately.
- Complete CPU FP32 validation for both endpoints and averages. Improvement >=
  0.003 BPB over current B triggers another three-repeat exact-checkpoint gate.
- Log all outcomes, including regressions and budget failures. No seed search,
  automatic budget extension or test scoring. Source hashes pinned for entire job.
- Single one-off Windows job, maximum six hours, existing battery safeguards.
  Rough estimate based on Stage-14 throughput: about one hour of training plus
  CPU checks, validation, loading and snapshots; roughly 1.5–3 hours wall time,
  hardware/thermal dependent. Long run may overfit; extra duration is not a promise.
- Paired-seed replication and final report/release QA remain later tasks. This
  stage prioritizes finding the next useful mechanism over duplicating all seeds.
