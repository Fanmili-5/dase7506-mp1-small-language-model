# MP1 结构重设计讨论稿 — 2026-09-21

状态：方案讨论，不是已实施或已验证的改进。本轮不改模型、不启动训练。
按用户要求，先分析机制，再实施；暂停原 Stage 13 的现有配方多 seed 复现。
旧冻结版本保持不变，所有新选择仅依据 validation，不调用 test。

## 1. 目标与边界

目标是在固定 WikiText-2 / BPE-2048 / 独立 256-token 因果窗口协议下，
找到比当前模型更好的质量—CPU 推理成本组合。架构不限，但不能使用外部
训练数据、预训练权重、未来 token、跨窗口状态或测试集调参。
CPU 时间 <= 基线 5 倍、峰值 RAM <= 4 GiB、解压推理资产 <= 64 MiB。
报告仍需同训练 targets 对照、关键机制消融，以及完整搜索成本。
这是一项课程优化任务，不要求原创架构，也不把新架构名字当成效果证据。

## 2. 已知证据及其解释边界

- 当前主干：6 层、宽度 256、8 头、RoPE / RMSNorm / SwiGLU、共享词嵌入与
  输出矩阵，5,247,744 参数。
- Stage 12：7,200 更新、batch 32，58,982,400 targets；训练计时 621.709 秒。
  原始终点 CPU FP32 validation BPB 1.551211927；预声明最后 5 个快照的
  权重平均为 1.547832503。新模型须分别比较终点和相同规则的平均，不能
  拿未经平均的新终点与旧平均混为结构对照。
- 该平均模型 Windows CPU 时间比 3.642570329，峰值 RSS 1,979,498,496 bytes，
  推理资产 23,237,899 bytes。时间余量约为当前耗时的 37%，不是新增参数
  的保证额度，也不是其他 CPU 上的通过保证。
- 已结束的 CUDA FP32 诊断：抽样训练 262,144 targets 平均 NLL 2.612094，
  完整 validation 376,599 targets 平均 NLL 3.270505。训练抽样不是全训练集
  BPB；差距不能单独证明过拟合或分布偏移，更不能证明只需继续训练。
- validation 中 148,196 / 376,599（约 39.35%）目标 token 在本窗口可见前缀
  中出现过。该组 NLL 2.518261，未出现组 3.758588。这个分组使用答案做
  事后诊断，模型和门控绝不能获得这一标签；重复 token 已经更容易预测，
  所以占比不是复制机制的预期增益。
- 前 16 个位置贡献约 7.11% 总验证 NLL，并非全部误差集中在窗口开头。
  窗口重置为固定协议，不能靠跨窗口缓存规避。

证据：`../results/stage12_summary.json`、`../results/stage12-evidence/run.json`、
`../results/stage12-generalization-diagnostic.json`。

## 3. 候选池与取舍

采用“问题优先、失败分析、复杂度是否值得”三个构思视角，先列候选，再收敛。

| 候选 | 本轮决定与理由 |
|---|---|
| 更宽更浅 Transformer | 保留：检查容量分配，不只加大规模 |
| 更深更窄 Transformer | 暂缓：已有短配方证据较弱，但不是永久排除 |
| 改 FFN 宽度占比 | 后续：主干形状确定后再拆分变量 |
| 独立输出矩阵 | 作为输出头对照；不是突破 softmax 秩限制的方法 |
| 两分量 Mixture of Softmaxes | 保留：检查输出分布表达能力 |
| 因果前缀复制分支 | 保留：检查显式重复建模是否互补 |
| 因果卷积 + 注意力 | 暂缓：需要更明确的局部模式误差证据 |
| 从零训练 LSTM | 允许且可做不同家族对照；目前缺少本协议 CPU/质量证据 |
| 状态空间 / 注意力混合 | 暂缓：短窗口收益未知，还需验证 CPU 实现与重置语义 |
| 紧凑训练集 n-gram 混合 | 备选：资产和查询时间须计入预算，先不引入另一套统计管线 |
| 训练集上自训练教师蒸馏 | 后续训练路线，不冒充结构比较；教师也只能用 train |
| 多模型概率集成 | 已有对照，CPU 余量较小；先提高单模型质量 |

## 4. 三个首轮结构候选

### A：宽浅主干，检查容量分配（实现风险最低）

将 6 层 × 256 宽改为 4 层 × 320 宽，保持 8 头、同一 SwiGLU 比例、
RoPE、RMSNorm、共享输出矩阵和 dropout 0.10。
通过当前工厂仅实例化计数，参数为 5,572,160，比控制多约 6.2%；尚未训练。
FP32 纯权重约 21.26 MiB，不代表完整 checkpoint 或资产总大小。

假设：较宽表示能比更多串行层更有效地使用相近参数预算。
反对理由：深度减少可能损失组合建模，宽矩阵也不保证 CPU 更快。
这是近似同参数、同 targets 的结构筛选，不是严格参数匹配或已知优胜方案。
若成功，先与同资源附近的形状做必要控制，不能把收益简单归因于宽度。

### B：现有主干 + 可学习前缀复制（机制变化最直接）

保留 6×256 主干。用最终隐藏状态 h_t 的 64 维 query 与 h_j 的 64 维 key，
只在 j <= t 上计算归一化注意力，将位置概率按已见输入 token x_j 求和。
使用 sigmoid 门控 g_t，由 h_t 预测：

`p(v | x_<=t) = (1-g_t) * p_vocab(v | h_t) + g_t * p_copy(v | x_<=t)`

两投影无 bias、门控有 bias，新增 33,025 参数，总计预计 5,280,769。
这是设计公式计算，尚未实现核验。增加一次窗口内注意力及 scatter 聚合，
CPU 开销未知；不能从参数少推断推理便宜。

假设：显式复制与词表预测互补，帮助预测已出现的 token / 词片段。
风险：BPE 高频碎片重复不等于实体重复；模型可能错误地偏向复制，损害
未出现 token。不直接移植词级论文的成绩或历史上下文缓存。
必须同时检查重复/非重复组 NLL 的变化、门控行为和总体 BPB。
移除分支且同配方重训是主消融；推理时临时关闭已训练分支只算辅助诊断。

### C：现有主干 + 两分量输出头（检验输出表达能力）

将单一 `softmax(E h_t)` 改为两个独立带 bias 的 256→256 tanh 投影，
共享原词嵌入输出矩阵 E，另用带 bias 的 256→2 softmax 门控：

`p(v | h) = sum_k pi_k(h) * softmax(E tanh(W_k h + b_k))[v]`，k=1,2。

新增参数预计 132,098，总计 5,379,842。词表投影做两次，额外 softmax 和
中间张量也有 CPU/RAM 成本。必须先资源预检，不能依据参数量保证通过。
最终接口返回归一化 log probability；训练需与该概率混合保持一致。

假设：单线性 softmax 输出头的表达能力限制了主干已有表示的利用。
限制：目前没有测出本模型的实际秩瓶颈；这只是可检验假设。
若候选有效，追加 K=1 的投影头控制来区分“额外非线性”与“概率混合”作用。
解除共享只放松输入/输出的约束，不会消除由隐藏维度带来的单头秩限制。
共享权重本身有已有语言建模依据，因此不预设解除共享一定更好。

## 5. 建议实验顺序与停止条件（待讨论后执行）

1. 实现时使用独立模块，不修改旧模型含义，不覆盖旧 checkpoint。每个候选
   先过因果性、归一化、batch/window 独立性、有限梯度和加载一致性测试。
2. 未训练模型先做 CPU FP32 资源预检：同机、同线程、同验证窗口、交替顺序。
   硬限制失败则不投入长训练；接近 5x 的方案标为边界方案，不当稳妥选择。
3. 首轮 A/B/C 各固定 seed 17，从零训练 7,200 更新，保持 Stage 12 相同的
   batch、优化器、学习率计划与验证频率。各 58,982,400 targets，共新增
   176,947,200 targets。先不混合 A/B/C，不筛 seed，不多维超参搜索。
4. 结构比较复用已完成的 Stage 12 控制，但须核验配置、样本 RNG、训练代码
   和固定数据的兼容性；若新功能要求公共训练逻辑改变，重跑匹配控制。
   相同 seed 不代表不同形状参数初始化逐元素可配对；它只固定首轮搜索。
5. 主比较为 7,200-step 终点对 1.551211927；次比较对每个模型统一平均
   6000/6300/6600/6900/7200 五个快照，对照为 1.547832503。不能为每个
   候选分别搜索平均窗口。平均不兼容的模型须说明，不能改选择规则救分。
6. 依据验证改善量作投入优先级，而非统计显著性判据：同口径降幅 >=0.01
   为优先；0.003–0.01 为次优；<0.003 不宣称明确胜出。配方匹配下变差的
   模型暂缓，不宣称架构永远不行。若曲线明确显示未收敛，可在看到后续结果
   前另立等额、对称的训练适配比较，不能单方面给候选加预算后称结构胜出。
7. 只为最有潜力的候选补关键消融，以及与控制配对的 seeds 23/42；报告全部
   差值，不以最幸运 seed 证明有效。之后才讨论组合互补机制。
8. 最终权重平均后的精确 checkpoint 必须重新跑三次 CPU FP32 gate，清点
   所有资产；冻结后才考虑最终 test。已有旧 test 分数不得参与路线选择。

本轮三方案是在比较潜力，不是承诺能到 1.4/1.3。其他人的 full-test BPB
也不能与我们的 validation BPB 直接排名。当前 10.4 分钟训练时长仅适用于
控制模型；新结构时间和显存需实测，先不据此承诺总用时。

## 6. 方法来源与适用范围

- [Pointer Sentinel Mixture Models](https://arxiv.org/abs/1609.07843)：生成与
  上下文复制的设计依据；本文方案为适配本课程独立窗口的候选，不是复现承诺。
- [Breaking the Softmax Bottleneck](https://arxiv.org/abs/1711.03953)：输出表达
  能力与混合 softmax 的依据；论文词级 PPL 与本协议 BPB 不直接可比。
- [Tying Word Vectors and Word Classifiers](https://arxiv.org/abs/1611.01462)：
  权重共享的已有依据，支持把解除共享视为待验证取舍而非必然升级。

参数估算和实验取舍仍需用户理解与确认。没有阅读或依赖同学的私有实现。
