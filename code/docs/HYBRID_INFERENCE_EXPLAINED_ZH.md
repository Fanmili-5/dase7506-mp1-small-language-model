# 当前混合模型与等价加速：实现说明

## 模型到底在预测什么

每个位置只输入当前窗口里已经出现的 token，输出下一个 token 在整个
2048 词表上的概率。输入窗口相互独立，最长256。模型包含三部分：

1. Transformer 主干与词表预测头：学习一般语言规律。
2. 前缀复制头：对已出现的位置做因果注意力，同一个 token 在多个位置
   出现时，把这些位置的注意力概率相加。它不能看到下一个正确答案。
3. 训练集统计头：用只从给定训练文本计算的二至五元统计，查询当前输入
   的后缀；没有匹配时退回低阶分布。统计表不是验证集或测试集答案缓存。

设词表分布为 v，复制分布为 c，统计分布为 q，模型学到的复制门值为 g。
当前固定混合比例 w=0.10，最终分布是：

`p = (1-w) * sigmoid(-g) * v + (1-w) * sigmoid(g) * c + w * q`

三个分布均覆盖同一2048词表，混合系数之和为1。最后返回 `log(p)`，而不是
只返回正确 token 的概率。验证脚本才用正确答案计算损失；预测函数不接收答案。

## Stage20 和 Stage21 改了什么

Stage20 把嵌套的对数空间混合改写成一次概率空间混合，再取一次对数。
Stage21 进一步处理统计头。原来的每阶递推是：

`q_i = b_i * q_(i-1) + s_i`

其中 b_i 是当前位置的回退系数，s_i 只在少量有统计记录的 token 上非零。
以两阶递推为例：

`q_2 = (b_2*b_1) * q_0 + b_2*s_1 + s_2`

所以可以先求出系数乘积，只计算一次稠密的基础分布，再加稀疏项。
旧实现每一阶都要读写整个词表；新实现减少了这部分内存读写，并直接把统计
贡献加到神经模型输出上。跨阶可能命中同一个 token，必须逐阶累加，不能用
会覆盖重复索引的写法。实现中训练路径保持原样，加速仅用于推理。

这里没有增加层数、训练轮数或新数据；参数、统计表、混合比例都没有变。
它解决的是同一个预测器能否满足 CPU 限时，不应当写成学习能力的新提升。

## 为什么还要做等价性检查

浮点运算换顺序不会保证逐位相同。实现保留行归一化，并在加载时检查统计头
的全词表正概率下界，防止极端神经输出造成 `log(0)`。不能靠裁剪概率或放宽
阈值来掩盖问题。

检查包括完整验证集每个位置、每个词表项的输出差异；归一化、因果性、窗口
独立性；序列化后所有权重和统计张量相等。然后使用未修改的官方 CPU FP32
评分器，按相同线程数做三轮 baseline/候选交替计时，记录峰值内存及所有推理
文件大小。小规模测试、Mac 计时和验证集 BPB 都不能替代最终资源检查。
